Space complexity: Space complexity in Big O notation measures the maximum amount of temporary memory an algorithm needs to run to completion relative to the size of the input data.

When calculating space complexity, computer scientists distinguish between two types of memory usage:
Input Space: The memory occupied by the input data itself.
Auxiliary Space: The extra or temporary memory allocated by the algorithm during its execution 
(e.g., local variables, new arrays, dynamic allocations).


Generally, when technical interviews or 
performance reviews refer to "space complexity," they are focusing primarily on Auxiliary Space, 
as you often cannot control the size of the incoming data.


Big-O — Upper Bound: Big-O to describe the worst-case complexity.

Big-O tells us an asymptotic upper bound on growth.

Big-Omega — Ω: Ω describes an asymptotic lower bound.

Big-Theta — Θ: Θ gives a tight asymptotic bound.


Big-O (O) - Upper BoundDescribes the worst-case growth rate.Means the function grows no faster than this limit.
Gives a ceiling for the algorithm's time or space.

Big-Omega (Ω) - Lower BoundDescribes the best-case growth rate.Means the function grows at least this fast.
Gives a floor for the algorithm's time or space.

Big-Theta (Θ) - Tight BoundDescribes the exact growth rate.Means the function grows both at least as fast as Ω and no faster than O.
Gives a precise, matching upper and lower limit.

List = a numbered row of houses (contiguous memory)
Go to house #5" → walk straight there → O(1) for list[i].

Is anyone named Sam on this street?" → knock on every door → O(n) for x in my_list. 
Insert a new house at the front → everyone else shifts down one → O(n).

Dict / Set = a library with a magic index card (hash table)
Run "Sam" through a hash function → it says "Shelf 42" → walk straight there → O(1) average for x in my_set / x in my_dict.
Collision (two titles → same shelf) → rare, but worst case degrades to O(n). Mention it, don't dwell.

Tuple = a sealed list
Same memory layout as a list → indexing is O(1) too. 
But it can never change — which is exactly why it's allowed to be a dict key or set member 
(Python needs a guarantee the hash never changes after it's stored).
